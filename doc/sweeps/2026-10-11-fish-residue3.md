# Fred Fish mass run - Phase 237e: residue III

Generated by `python3 -m rdd massrun report` (Phase 232, 237b-e).

9943 executables from the Fred Fish disks, each run without input on lxa (v0.11.88) and on AmigaOS 3.1
(reference instances 0-19).  The run time and the batch emulation are those of Phase 237d
(`doc/sweeps/2026-10-10-fish-residue2.md`): about 12 emulated seconds, a fresh system directory per batch
of 25 programs, each program as `LXAREF:p/<id>/<name>`.  Programs whose reference outcome depends on the
batch (`ENVIRONMENT_DEPENDENT`), on memory contents or the memory map (`MEMORY_DEPENDENT`), and programs
that finish sooner than the reference (`FINISHED_SOONER`) are listed apart; every entry was checked on the
reference.

Gate (roadmap Phase 237e): lxa-only hangs and missing windows <= 20 - **met: 32 -> 14**; no lxa-only crash
class with 2 or more programs - **met** (largest class 1); the suite flakes found and fixed - **met**:

- a write to an unmapped address (exec/getmsgnull writes through ROM code bytes taken as list pointers)
  started lxa's interactive debugger, which read the stdin every test shares with its runner (a stray
  "s" single-stepped the emulator, other input made it wait); the debugger now needs `-d` and a terminal
  and never prompts in liblxa (`tests/rdd/test_stdin.py`);
- a second emulator run in the same process (GTest drivers) started from the first run's CPU registers
  and FPU state, host file descriptors, open-file table and display input state; found with per-frame
  RAM dumps and instruction traces of both runs.

## Memory-dependent programs

Their outcome depends on the bytes of the Kickstart ROM or low memory (`MEMORY_DEPENDENT` in massrun.py).

- fish-0099/A-Render/programs/LATHE (lxa crash, 3.1 hang): parses its stdin buffer (AllocMem(1032) without MEMF_CLEAR) although Read() returned 0 at end of file: the answers are whatever the memory held (Phase 237d)
- fish-0363/WO/wo1.0d (lxa crash, 3.1 window): reads IntuitionBase->ActiveScreen through a NULL IntuitionBase (Kickstart code via the vector table, Phase 237)
- fish-0365/Password/loop (lxa crash, 3.1 window): its VTBeep task starts with A4 = 0 (as on 3.1, probe exec/taskregs) and compares its stack pointer with the vector at 744(A4): on the reference the stack is in fast RAM above the ROM, on lxa below it, so lxa takes the stack-overflow path (memory map, Phase 240)

## Environment-dependent programs

Their reference outcome depends on libraries other programs of the same reference batch installed (`ENVIRONMENT_DEPENDENT` in massrun.py).

- fish-0101/Midi/util/mm (lxa hang, 3.1 exit): midi.library cannot route from MidiIn on the reference: lxaprobe holds the serial port
- fish-0224/MoreIsBetter/V (lxa exit, 3.1 window): runs SYS:Utilities/More, a Workbench 3.1 program lxa does not ship
- fish-0398/Formatter/Formatter (lxa exit, 3.1 window): needs arp.library V39+: on the reference DClock, run before it in the same batch, opened the arp.library of its own drawer, which stays in memory
- fish-0422/PopUpMenu/PopUpMenu.run (lxa hang, 3.1 exit): PopUpMenu, run before it in the reference batch, left its "Reply" port: PopUpMenu.run sends it the quit message and exits; alone it waits on the reference too
- fish-0429/V/V (lxa exit, 3.1 window): runs SYS:Utilities/More, a Workbench 3.1 program lxa does not ship
- fish-0431/A68Kex/say (lxa exit, 3.1 window): the reference's Workbench 3.1 has no translator.library (say shows its "not found" requester), lxa has one; neither has narrator.device
- fish-0638/ShellTimer/ShellTimerDaemon (lxa hang, 3.1 exit): ShellTimer, run before it in the reference batch, had already started the daemon
- fish-0763/MidiSyn/MidiSyn (lxa hang, 3.1 exit): the reference's serial port is held by lxaprobe ("Serialport not available")
- fish-0896/Riff/riff (lxa exit, 3.1 window): needs reqtools.library: on the reference DA2.5, run before it in the same batch, opened the reqtools.library of its own drawer, which stays in memory
- fish-0955/MuroloUtil/Kickmaker (lxa hang, 3.1 exit): on the reference AllocMem(MEMF_CHIP) failed after the earlier programs of its batch ("Can't alloc memory", exit); alone it waits for RETURN there too, as on lxa
